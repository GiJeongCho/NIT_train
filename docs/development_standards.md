# 개발표준 (Development Standards)

> 대상: `NIT_train/src/v1/` 애플리케이션
> 목적: 구조·코드·설정·문서 작성의 일관성 유지
> 기준: 추론 서비스(`tracker_py/docs/development_standards.md`)를 따르되, 학습 서비스에
> 고유한 항목(잡·워크스페이스·라벨 규약)을 추가한다.
> 작성일: 2026-07-29

---

## 1. 프로젝트 구조 표준

앱 루트는 `src/v1/` 이며 계층을 분리한다.

```
src/v1/
├── main.py            # 엔트리포인트 (uvicorn 구동)
├── app.py             # FastAPI 앱 + lifespan + 예외→HTTP 변환
├── core/              # 횡단 관심사
│   ├── config.py      # 환경변수 기반 Settings (설정의 단일 소스)
│   └── store.py       # 워크스페이스 레이아웃 + 원자적 JSON IO
├── api/               # FastAPI 라우트 (얇게 유지: 검증 + 서비스 호출)
│   └── routes.py
├── services/          # 비즈니스 로직
└── utils/             # 순수 함수(좌표 변환 등)
```

### 계층 책임 원칙

- **api(routes)**: HTTP 입출력·검증만. 로직은 services 로 위임. **얇게 유지.**
- **services**: 실제 처리/상태. HTTP를 모른다(`HTTPException` 을 올리지 않는다).
- **core/config**: 모든 런타임 동작은 환경변수로 조정. 설정의 단일 소스.
- **core/store**: 파일 경로를 아는 유일한 모듈. services 는 경로 문자열을 조립하지 않는다.
- **utils**: 부수효과 없는 순수 함수만. 설정·파일을 읽지 않는다.

### 예외 처리 규약

services 는 **표준 예외**를 올리고, `app.py` 의 핸들러가 HTTP로 번역한다.
라우트를 `try/except` 로 덮지 않기 위한 규약이다.

| 예외 | HTTP | 언제 |
|---|---|---|
| `ValueError` | 400 | 잘못된 입력, 상태 위반(승인 조건 미달 등) |
| `KeyError` | 404 | 존재하지 않는 video/frame/dataset/run |
| `FileNotFoundError` | 410 | 등록은 됐지만 원본 파일이 사라짐 |

## 2. 설정 표준

- 모든 튜닝 가능한 값은 **환경변수**로 노출하고 `core/config.py` 의 `Settings` 에 추가한다.
- 명명 규칙: 접두사 `NIT_TRAIN_`, 대문자 스네이크. 예) `NIT_TRAIN_EXTRACT_FPS`.
  - 추론 서비스가 `NIT_` 를 쓰므로 **같은 호스트에서 충돌하지 않도록** 접두사를 분리한다.
- `Settings` 필드(기본값) + `from_env()` 매핑(`_env_int/_env_float/_env_bool/_env_str/_env_path/_env_list`)을 **쌍으로** 추가한다.
- 새 환경변수를 추가하면 `docs/development_environment.md` 의 표와 `README.md` 를 갱신한다.
- 사용자별·프로젝트별로 바뀌는 상태(클래스 목록 등)는 환경변수가 아니라 **워크스페이스 파일**에
  둔다. 환경변수는 초기값만 제공한다.

## 3. 코드 스타일

- `from __future__ import annotations` 사용, 타입힌트 명시.
- 모듈 상단에 역할을 설명하는 docstring(한국어).
- **주석은 "왜"를 적는다.** 코드가 자명하게 설명하는 "무엇"은 적지 않는다.
  - 특히 "이 값이 왜 이 숫자인지"(예: `workers=4` 의 Windows RAM 이슈)는 반드시 남긴다.
- 외부 입력/리소스는 방어적으로 처리(영상 열기 실패, fps 0, GPU 미가용, 하드링크 실패 폴백).
- 싱글톤은 모듈 레벨 `get_xxx()` 게터로 lazy 초기화(`get_settings`, `get_detector`).
- 무거운 초기화(모델 로드/워밍업)는 기본적으로 하지 않는다. 학습 서비스는 대기 시간 대부분
  모델이 필요 없다. 필요하면 `NIT_TRAIN_PRELOAD=1`.

## 4. 데이터 안전 표준

라벨링은 사람의 시간이 들어간 작업이다. **작업 손실을 코드 레벨에서 막는다.**

- 모든 JSON 쓰기는 `store.write_json()` 을 쓴다(임시파일 + `os.replace` = 원자적).
  직접 `json.dump(open(...))` 하지 않는다. 중간에 죽으면 반쯤 쓰인 라벨이 남는다.
- 재실행(자동 라벨 재추출)은 **기본적으로 사람 수정을 보존**한다(`overwrite="skip"`).
  덮어쓰는 모드는 명시적으로 요청해야 한다.
- 파괴적 동작은 이력을 남기는 대안을 우선 제공한다(삭제보다 `status="rejected"`).
- 클래스 목록은 순서 변경·삭제를 거부한다. 인덱스가 과거 라벨의 정답이기 때문이다.
- 외부에서 온 id는 경로로 쓰기 전에 `store.safe_id()` 로 검증한다(경로 탈출 방지).

## 5. 잡(백그라운드 작업) 표준

수 초 이상 걸리는 작업은 HTTP 요청 안에서 처리하지 않는다.

- 스레드 잡(`services/jobs.py`): 프레임 추출, 데이터셋 빌드.
  - 잡 본문은 루프마다 `job.check_canceled()` 를 호출한다(협조적 취소).
  - 진행률은 `job.set_total()` / `job.advance()` 로 갱신한다.
  - **잡을 띄우기 전에 입력을 검증한다.** 잡 안에서 죽으면 사용자가 늦게 안다.
  - 같은 대상에 대한 중복 실행은 `jobs.active_for()` 로 막는다.
- 프로세스 잡(`services/trainer.py`): 학습.
  - GPU를 오래 점유하거나 크래시가 서비스에 전이될 수 있는 작업은 **자식 프로세스**로 분리한다.
  - 자식은 앱 모듈을 import 하지 않는다(Windows spawn 재import 부작용 방지).
  - 상태는 자식이 `state.json` 에 쓰고 부모는 읽기만 한다.
  - 중단은 프로세스 **트리**를 종료한다(워커가 남으면 GPU 메모리를 계속 잡는다).

uvicorn 워커는 **1개로 고정**한다. 잡 레지스트리와 로드된 가중치가 프로세스 메모리에 있어서,
워커를 늘리면 진행률 조회가 다른 워커로 가 404가 난다.

## 6. 라벨/데이터셋 규약

- 라벨의 내부 표현은 **픽셀 좌표 4점 폴리곤** 하나로 통일한다.
  축정렬 박스는 그 특수한 경우이며, 태스크별 변환은 `utils/geometry.py` 에서만 한다.
- 라벨의 정답은 `class_name`(문자열)이고 `class_id` 는 캐시된 인덱스다.
  데이터셋 빌드에서 이름 → 인덱스를 다시 계산한다.
- **부분 라벨은 학습에 넣지 않는다.** 미확정 객체가 있는 프레임은 승인 단계에서 막고,
  그래도 남으면 데이터셋 빌드에서 제외하며 사유를 `manifest.excluded` 에 집계한다.
- 데이터셋은 **스냅샷**이다. 빌드 시점의 이미지를 링크/복사해 고정하고, 이후 라벨 수정에
  영향받지 않는다. 무엇으로 만들었는지는 `manifest.json` 에 남긴다.
- 분할은 누수를 기본으로 방지한다(`split_mode="chunk"`). 무작위 분할은 명시적 선택으로만.

## 7. 문서화 표준

- 문서는 `NIT_train/docs/` 에 둔다.
  - `architecture.md` — 전체 파이프라인·설계 결정과 근거
  - `api.md` — API 레퍼런스 + 프런트 연동 순서
  - `labeling_workflow.md` — 사용자 관점 워크플로(화면 설계 근거)
  - `dataset_format.md` — 라벨/데이터셋 포맷과 클래스 id 규약
  - `development_environment.md` — 셋업/실행/환경변수
  - `development_standards.md` — 본 문서
- 동작이 바뀌면 관련 문서를 **같은 변경에서 함께** 갱신한다(코드-문서 동기화).
- 설계 결정은 결론만 쓰지 말고 **왜 그렇게 했는지**를 남긴다. 6개월 뒤 되돌리려는 사람이
  같은 함정을 다시 밟지 않게 하는 것이 문서의 목적이다.

## 8. 검증 표준

- 파이프라인을 바꾸면 `test/smoke_api.py` 를 돌려 전 구간이 통과하는지 확인한다.
- 스모크 테스트는 **임시 워크스페이스**에서 돌고 실제 데이터를 건드리지 않는다.
- 조용히 틀리기 쉬운 것(좌표 정규화, 라벨 컬럼 수, 분할 비율, 이미지/라벨 개수 일치)은
  반드시 단언(assert)으로 확인한다. 이런 버그는 학습을 다 돌린 뒤에야 드러난다.
- 학습 경로 변경 시에는 `python smoke_api.py --train` 으로 1 epoch 까지 검증한다.

## 9. 의존성/버전 표준

- `requirements.txt` 는 **이 앱이 직접 import 하는 것만** 담는다.
- `torch`/`torchvision` 등 GPU 스택은 conda 환경 또는 도커 base 이미지가 제공한다.
- 런타임에 패키지를 설치하려 드는 의존성은 미리 고정한다.
  (예: `lap` 이 없으면 ultralytics 트래커가 pip 설치를 시도해 **폐쇄망에서 실패**한다.)
- 새 의존성은 패키지 매니저로 최신 호환 버전을 추가하고, 임의 버전을 지어내지 않는다.

---

## 10. Git / 변경 관리

- 커밋은 사용자가 명시적으로 요청할 때만 생성한다.
- 한 커밋은 한 가지 논리적 변경으로 작게 유지하고, "왜"를 메시지에 적는다.
- 비밀정보(`.env`, 자격증명)는 커밋하지 않는다.
- 대용량 산출물은 버전관리에서 제외한다: `workspace/`, `*.pt`, `*.engine`, `*.onnx`.
