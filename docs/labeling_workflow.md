# 라벨링 워크플로 (사용자 관점)

> 대상: `NIT_train_front` 화면 설계 + 운용자 매뉴얼
> 작성일: 2026-07-29

영상 한 편이 학습 데이터가 되기까지 사람이 하는 일과, 그때 화면이 무엇을 보여줘야
하는지를 정리한다. 목표는 **사람이 판단해야 하는 것만 사람에게 묻는 것**이다.

---

## 전체 6단계

```
① 영상 올리기 → ② 쓸 구간 고르기 → ③ 자동 라벨 돌리기
             → ④ 객체별 클래스 지정 → ⑤ 프레임 검수·승인 → ⑥ 데이터셋 + 학습
```

체감 작업량은 ④와 ⑤에 몰린다. ④를 제대로 쓰면 ⑤가 확인 작업으로 줄어든다.

---

## ① 영상 올리기

- 업로드: `POST /api/videos` (multipart)
- NAS에 이미 있으면 복사 없이 등록: `POST /api/videos/path`

등록되면 fps·해상도·길이가 나온다. 이 값으로 타임라인 눈금을 그린다.

**화면 요소**: 영상 목록(썸네일 + 길이 + 라벨링 진행률 배지), 드래그&드롭 업로드,
업로드 진행률.

---

## ② 쓸 구간 고르기 (정상 / 비정상)

`<video src="/api/videos/{id}/stream">` 위에 타임라인을 얹고 구간을 드래그한다.

| 구간 | 뜻 | 예 |
|---|---|---|
| **정상** (여러 개) | 학습에 쓸 부분 | 표적이 안정적으로 보이는 구간 |
| **비정상** (여러 개) | 못 쓸 부분 | 이륙/착륙, 급기동 흔들림, 렌즈 오염, 노출 폭주, 구름 통과 |

저장: `PUT /api/videos/{id}/segments`

계산 규칙은 단순하다.

```
실제 추출 대상 = (정상 구간 합집합) − (비정상 구간 합집합)
```

- 겹치는 같은 종류 구간은 자동 병합된다.
- **정상 ∩ 비정상 = 비정상.** "쓰지 말라"가 항상 이긴다.
- 정상 구간을 하나도 안 찍으면 영상 전체를 정상으로 본다. 짧은 클립은 비정상만 찍으면 된다.

저장 응답의 `selection_ranges` 를 타임라인에 다른 색으로 겹쳐 그려서, 사용자가
**뽑기 전에** 대상을 눈으로 확인하게 한다(`GET /api/videos/{id}/selection` 로도 조회 가능).

**화면 요소**: 비디오 플레이어, 구간 드래그 타임라인(정상=초록/비정상=빨강),
구간 목록 테이블(시작·끝·길이·메모), 실제 대상 구간 오버레이 + 총 길이.

## ③ 자동 라벨 돌리기

`POST /api/videos/{id}/extract` → 백그라운드 잡. `GET /api/jobs/{job_id}` 로 진행률.

이 단계가 하는 일:

1. 대상 구간에서 **초당 2장**(기본) 샘플링
2. 640×480 정규화 후 JPEG 저장
3. YOLO 추론 → 박스 초안 생성
4. 트래킹으로 `track_id` 부여

**초당 몇 장?** 30fps를 전부 뽑으면 1분에 1800장이고 인접 프레임은 거의 같은 그림이다.
검수 부담만 늘고 학습 가치는 거의 없다. 움직임이 느리면 1, 빠르면 4~5 정도.

**conf(신뢰도)는 낮게.** 기본 0.25로 운영 추론보다 낮다. 초안은 **지우는 게 그리는 것보다
싸기** 때문이다. 오탐 몇 개를 지우는 비용 < 빠뜨린 표적을 새로 그리는 비용.

**다시 돌릴 때**(`overwrite`):

| 값 | 동작 | 쓸 때 |
|---|---|---|
| `skip` (기본) | 기존 라벨 그대로 둠 | 중단된 작업 이어서 |
| `auto` | 검수 전 초안만 새 모델로 갱신 | 1차 학습 모델로 초안 품질 올리기 |
| `all` | 전부 재생성 | 처음부터 다시. **사람 수정이 사라진다** |

**화면 요소**: 추출 옵션 폼(fps/모델/conf/재실행 정책), 진행률 바 + 예상 남은 시간
(`rate_per_sec` 사용), 취소 버튼.

## ④ 객체별 클래스 지정 ← 여기가 핵심

`GET /api/videos/{id}/tracks` 로 **객체 목록**을 받는다.

```json
{"items": [
  {"track_id": 3, "frames": 287, "model_class_name": "truck",
   "class_name": null, "resolved": false, "avg_score": 0.81,
   "first_frame": "f000012", "last_frame": "f000560"}
]}
```

객체 하나를 고르고 클래스를 지정하면:

```
POST /api/videos/{id}/propagate  {"track_id": 3, "class_name": "Panther_II"}
→ {"frames": 287, "objects": 287}
```

**287개 프레임의 라벨이 한 번에 채워진다.** 라벨링 시간이 프레임 수가 아니라 **객체 수**에
비례하게 되는 지점이다. 영상 한 편에 표적이 5대면 클릭 5번이 기본 작업량이다.

**화면 요소**: 객체 카드 목록(대표 프레임 크롭 이미지 + 등장 프레임 수 + 모델 힌트 +
클래스 셀렉트). 미확정(`resolved: false`) 객체를 위로 정렬. 카드 클릭 시 그 객체가 처음
등장하는 프레임으로 이동.

> 대표 크롭 이미지는 `first_frame` 의 `image` 를 받아 프런트에서 `bbox` 로 잘라 쓰면 된다.

## ⑤ 프레임 검수·승인

④로 대부분이 채워지고 나면, 남는 일은 세 가지다.

1. **자동 라벨이 놓친 표적** → 박스를 새로 그린다
2. **오탐** → 박스를 지운다
3. **박스 위치가 어긋난 것** → 꼭짓점을 옮긴다

`GET /api/videos/{id}/frames?status=pending` 으로 남은 프레임만 본다. 목록의
`n_unresolved > 0` 인 것부터 처리하면 된다.

편집 결과는 `PUT /api/videos/{id}/frames/{frame_id}` 로 **objects 전체를 통째로** 보낸다.
`status: "approved"` 를 같이 보내면 검수 완료 처리된다.

### 승인 규칙 (중요)

**클래스가 정해지지 않은 객체가 하나라도 있으면 승인이 거부된다(400).**

```json
{"detail": "클래스가 정해지지 않은 객체가 있어 승인할 수 없습니다: ['o1','o2']. ..."}
```

"라벨링은 모든 부분을 해야 한다"는 규칙을 여기서 강제한다. 일부만 라벨된 이미지는
라벨 없는 객체를 배경으로 학습시켜 **모델을 적극적으로 망가뜨린다.** 그 프레임을
아예 안 쓰는 편이 낫다.

- **객체가 0개인 프레임은 승인된다.** 배경(negative) 샘플로 유효하고 오탐을 줄여준다.
- 쓸 수 없는 프레임은 지우지 말고 `status: "rejected"` 로 남긴다(이력 보존).
- 전체 승인: `POST /api/videos/{id}/frames/status`. 조건을 못 채운 프레임은 건너뛰고
  이유를 모아 돌려주므로, 그 목록을 그대로 "남은 할 일"로 보여주면 된다.

**화면 요소**: 좌측 프레임 썸네일 그리드(상태별 필터), 우측 캔버스 편집기
(이미지 + poly 드래그/추가/삭제 + 클래스 셀렉트), 단축키(다음/이전/승인/삭제),
상단 진행률 바(`GET /api/videos/{id}/progress`).

> 캔버스에 그릴 때는 `image`(원본)를 받아 프런트가 `poly` 를 직접 그린다.
> `image?overlay=1`(서버 렌더)은 빠른 확인·썸네일용으로만 쓴다.

## ⑥ 데이터셋 + 학습

여러 영상의 라벨링이 끝나면 **학습에 쓸 영상들을 골라** 데이터셋을 만든다.

```
POST /api/datasets  {"name":"drone-2026-07", "video_ids":[...],
                     "base_datasets":["C:/project/tracker_py/train_data/preprocessed_obb"]}
```

`task` 는 생략하면 서버 기본값 `obb` 다. `base_datasets` 로 기존 데이터셋을 함께 넣으면
새로 라벨한 프레임과 합쳐 하나의 스냅샷이 된다(클래스는 이름으로 매핑, 원래 분할 유지).

manifest의 `class_histogram`, `excluded`, `warnings` 를 화면에 그대로 보여준다.
"왜 프레임이 이것밖에 안 들어갔지?"를 사용자가 스스로 해결할 수 있게 하는 것이 중요하다.

```
POST /api/train  {"dataset_id":"...", "epochs":100}
→ GET /api/train/{run_id} 폴링 (epoch/mAP/로그)
```

학습이 끝나면 `POST /api/models/promote` 로 이름을 붙여 배포 후보로 등록한다.

**화면 요소**: 영상 다중 선택 + 데이터셋 옵션, 클래스 분포 막대그래프, 제외 사유 표,
학습 폼(모델/epochs/batch/device), 학습 진행률 + mAP 곡선 + 로그 콘솔, 모델 카드.

## 부트스트랩: 첫 초안을 만들 모델이 없다

**사전학습 가중치는 이 도메인에서 아무것도 잡지 못한다.** `yolo26l-obb.pt`(DOTA 15)와
`yolo26l.pt`(COCO 80) 모두, 탑다운 드론 영상에서 10px 크기로 보이는 전차를 `conf=0.05`
에서도 하나도 탐지하지 못했다(실측). 그래서 자동 라벨 초안이 0개로 나오는 것이 **정상**이다.

시작 모델은 이렇게 만든다.

```
0차: 이미 라벨된 폴더를 등록                       ← 가장 빠른 길
     POST /api/datasets/import
       {"path": "C:/project/tracker_py/train_data/preprocessed_obb", "copy": false}
     POST /api/train {"dataset_id": "..."}          → 1 epoch만으로도 mAP50 0.95 수준
     POST /api/models/promote {"run_id": "...", "alias": "drone-v1"}
```

기존 데이터셋이 없다면 라벨링 화면에서 수십~수백 장을 직접 그려 같은 절차를 밟는다.
그 뒤부터는 되먹임이 돈다.

```
1차: extract 시 model="models/drone-v1.pt" → 박스 + 클래스까지 맞게 제안
     → 사람은 틀린 것만 고침 (작업량 급감) → 새 라벨 + 기존 데이터셋 병합 학습 → drone-v2
2차: … 반복
```

`overwrite: "auto"` 를 쓰면 이미 검수한 프레임은 건드리지 않고 미검수 초안만 새 모델로
갱신된다. 이 되먹임이 MLOps 파이프라인의 본체이고, 회차가 쌓일수록 사람 개입이 줄어든다.

## 자주 막히는 지점

| 증상 | 원인 | 해결 |
|---|---|---|
| 자동 라벨 초안이 0개 | 사전학습 가중치가 도메인 밖(정상) | 위 **부트스트랩**대로 승격 모델을 만들어 `model` 로 지정 |
| 추출 대상 구간이 비어 있다 | 정상 구간 전체가 비정상과 겹침 | `GET .../selection` 으로 확인 후 구간 조정 |
| 병합이 400으로 거부 | 소스 클래스가 목록에 없음 / 태스크 불일치 | `PUT /api/classes` 로 뒤에 추가, 또는 태스크를 맞춘다 |
| 승인이 계속 400 | 미확정 클래스 객체 | `GET .../tracks` 에서 `resolved:false` 객체 처리 |
| 데이터셋 프레임이 너무 적다 | 승인된 프레임만 들어감 | manifest의 `excluded` 확인, 일괄 승인 실행 |
| valid가 0이다 | 프레임이 너무 적음 | 프레임을 더 모으거나 `splits` 조정 |
| 학습이 시작 직후 실패 | 모델 태스크 ≠ 데이터셋 태스크 | [dataset_format.md](dataset_format.md) §7 참고 |
| 후반 epoch에서 학습이 죽음 | Windows DataLoader 워커 RAM 부족 | `workers` 4 → 2 |
